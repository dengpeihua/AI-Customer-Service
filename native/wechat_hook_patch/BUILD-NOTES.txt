WeChat-Hook QueryDB safe scanner patch
======================================

assets/hook/version_hook.dll is built from aixed/WeChat-Hook, tag v411027_
(commit 53ba84edec4414c48abcbe86d6efa98eac1fcbfd), with
querydb-empty-result.patch applied.

The upstream scanner searches process memory for every occurrence of the
SQLite VFS pointer. Most occurrences are not live sqlite3 handles. Calling
SQLite on an arbitrary candidate can return no PRAGMA rows, throw from JSON
row-zero access, or raise a Windows access violation. The first case made
/QueryDB/GetAllDBName return HTTP 500; continuing past it without stronger
validation could terminate WeChat.

The patch now:

- checks the candidate memory range and stable sqlite3 structure fields before
  calling any SQLite routine;
- reads PRAGMA database_list directly instead of indexing an assumed JSON row;
- protects prepare, step, column access, and finalize with Windows SEH; and
- starts the otherwise-never-updated g_IsLogin gate at 1; the Python ownership
  and account guards still fail closed before an adapter can read the service;
- is recognized by PE timestamp and image size, so the Python compatibility
  patch reports it ready without writing a legacy RVA into the new image; and
- skips empty paths and faulting candidates without changing messaging offsets,
  SQL used by the widget, account routing, or HTTP routes.

Build artifact:

- target: Windows x86-64
- compiler: Zig 0.15.2 C++ (x86_64-windows-gnu), C++20, optimized
- SHA-256: a2cd8623b1fd0d8addc71ca96621e9be384492161524f9d8c8832f762ed6a962
- exported proxy functions: all 17 exports from upstream version.def

Validation:

- the DLL loads outside WeChat and its proxied GetFileVersionInfoSizeW export
  calls the real system version.dll;
- an isolated WeChat process was built with g_IsLogin forced to 1 so the full
  candidate scan runs even without an account. GetAllDBName returned HTTP 200
  in 2.925 seconds and the process remained alive; and
- a DB-only validation build was loaded into a normally logged-in WeChat
  process on a separate port. GetAllDBName found 22 databases in 5.343 seconds,
  the project adapter listed 10 sessions in 0.054 seconds and read 20 messages
  in 1.037 seconds, and the WeChat process remained alive.

The upstream 606208-byte artifact remains at
assets/hook/version_hook_upstream.dll for rollback and comparison.
